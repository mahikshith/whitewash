# Repository audit and integration decisions

Research snapshot: 18 October 2026. This is a targeted code review of 15 public repositories, not a security certification or a claim to have read every file. The [source manifest](source-manifest.json) records 155 retrieved files, exact commits, URLs and SHA-256 hashes. Retrieval coverage differs from the inspection paths below. No private source, paid detector, model training or GPU inference was accessed.

## What these repositories do

They cover editorial instructions, statistical classifiers, keyed watermarking, watermark attacks, benchmarking, and document extraction. Those are separate components. None supplies a production application that reliably removes every provider watermark while preserving arbitrary documents.

## Concrete findings

### P1: research export repeats the last detector result

In the random-walk repository's [detection exporter](https://github.com/hlzhang109/impossibility-watermark/blob/fc1da1d09dc3f22377ac1d70526765511a826270/text/evaluation/pipelines/detection.py#L105), each historical row receives the current loop's detect_result and index. A two-sample synthetic execution returned scores [0.1, 0.9] in memory but wrote [0.9, 0.9] with duplicate IDs [1, 1]. This can corrupt exported comparisons. It does not establish that the paper used this export or that its findings are invalid. Export each stored result and stable sample ID, then round-trip the file before using it.

### P1: configured attack steps are not a hard budget

The [random-walk loop](https://github.com/hlzhang109/impossibility-watermark/blob/fc1da1d09dc3f22377ac1d70526765511a826270/text/evaluation/tools/text_editor.py#L197) continues while a score is above its target even after total_steps is exceeded. With total_steps=2 and stubbed positive detection, the audit stopped it after seven perturbations. Replace this with independent attempt, time, token and monetary caps. Avoid logging private drafts; the inspected implementation prints originals/candidates.

### P2: RAID ignores include_all=False at its public entry point

[run_evaluation](https://github.com/liamdugan/raid/blob/d847408c2fed266d472a422745d303b278910cd8/raid/evaluate.py#L226) accepts include_all but does not pass it to compute_scores at line 239. A synthetic stub confirmed the downstream default remained True. Pass the argument explicitly; add an integration assertion covering returned groups.

### P2: a Markdown guard misses tilde-fenced code

[Humanizer-zh's structure check](https://github.com/op7418/Humanizer-zh/blob/f4518a8eab97b8bfebc66a89d34320a89bef6930/tests/check_structure.py) detects the tested backtick-fence mutation but misses the same change inside a tilde fence. Protect both and unclosed fences, and use parser-level protection for richer Markdown. Do not present a regex snapshot as complete structural preservation.

The [focused check results](source-check-results.json) document these executions. They extracted inspected functions with synthetic stubs to avoid heavyweight model dependencies. These are narrow reproductions, not end-to-end model runs. The scratch harness is not a redistribution of upstream source.

Run `python scripts/reproduce-research.py` from the repository to reproduce the four code checks. It retrieves only the four reviewed public source files if missing, verifies their manifest hashes, and runs the inspected paths with stubs. Outputs and fetched sources stay in ignored `.research/`. It does not run model inference or the separate Humanizer packaging check.

## What to carry into Whitewash

Keep a browser-local cleanup engine and immutable source text; show each edit before export. Make a later model adapter produce proposed edits, not overwrite files directly. Validate facts, protected spans and structure before presenting a result. Keep model inference, document parsing and detector experiments in separate bounded workers.

For a controlled watermark lab, start with SynthID and MarkLLM, one scheme at a time. Use paired originals/edits with stable IDs, independent thresholds, hard budgets and quality adjudication. Compare a plain paraphrase baseline before investing in RL. For document support, prototype native DOCX part patching separately from extraction libraries. Evaluate multilingual behavior explicitly: Chinese punctuation, joiners, RTL controls and emoji are not disposable artifacts.

Public GitHub issue [399](https://github.com/guillaumemeyer/watermarks-remover/issues/399) reports a format-detection error that can leave metadata unremoved. This is a report, not our reproduction. Open PR [405](https://github.com/guillaumemeyer/watermarks-remover/pull/405) proposes stronger human false-positive benchmarking and explicit fallback-backend reporting; it is not an implemented feature at the pinned revision or a completed real-corpus result. Both inform our validation requirements.
